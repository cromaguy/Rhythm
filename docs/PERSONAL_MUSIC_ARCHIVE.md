# T2Rhythm 개인 음악 보관함

설정 → **내 음악 보관함**에서 사이트 소스, 음원 갱신, 영구 백업과 청취 기록을 관리합니다. API 관리와 라이브러리 아트워크 설정도 같은 소스 설정을 공유합니다.

## 음원 갱신

- 기본은 빈 태그·이미지·가사만 채웁니다. 전체 덮어쓰기 또는 제목/아티스트/앨범/장르/연도/이미지/가사별 강제 덮어쓰기를 선택할 수 있습니다.
- 제목·아티스트와 곡 길이를 확인합니다. 기본 오차 3%, 사용자 지정 0–30%, 표시 시간 반올림용 최소 1초입니다. 길이가 없거나 후보가 여럿이면 자동 기록하지 않습니다. 길이 확인을 끄는 것은 사용자의 명시적인 설정입니다.
- 기본 사이트 순서는 **벅스 → 멜론 → 지니**입니다. 각 사이트를 켜거나 끄고 앨범·노래 이미지 소스를 선택할 수 있습니다. 아티스트 이미지의 기존 로컬 전용/사용 안 함 정책도 유지합니다.
- 가사 API 목록에는 통합 음악 사이트 소스와 벅스·멜론·지니 각각의 우선 선택이 있습니다. 기존 Rhythm 가사 API 기본값, 소스 설정과 폴백은 유지합니다. 가사 항목을 명시적으로 강제 덮어쓰기하면 온라인 조회를 먼저 새로 실행하며 API 우선순위와 폴백은 그대로 사용합니다.
- 갱신한 값과 이미지는 실제 음원 태그에 기록합니다. 가사는 TXT/LRC/단어 JSON을 저장하고, 지원되는 음원에 가사를 내장합니다. Android의 파일 쓰기 허용이 없거나 재생 중이면 쓰기가 대기합니다.
- 사이트별 직렬 요청·3초 간격·Retry-After 및 차단 대기를 적용합니다. CAPTCHA나 로그인 제한을 우회하지 않습니다.

## 영구 파일과 복원

기존 `Documents/RhythmBackups` 폴더 아래 `T2Rhythm/`를 사용합니다. Android의 저장소 제한이 있으면 백업/복원 화면 또는 내 음악 보관함에서 **같은 폴더를 한 번 선택**해 접근 권한을 부여하세요. 다른 폴더를 지정할 수도 있습니다.

- `music_metadata/records/`: 출처가 포함된 원본 정보 JSON
- `music_metadata/entities/artists/`, `entities/albums/`: 이름별 metadata.json, about.txt, artwork.jpg
- `music_metadata/images/`: 앱이 소유하는 영구 이미지
- `music_metadata/lyrics/`: 가사 JSON, TXT, LRC와 단어별 JSON
- `music_metadata/originals/`: 갱신 전 태그와 원래 이미지
- `music_metadata/audio_features/`: PCM 지문, 파형 요약, 음향 특성
- `music_metadata/settings/`: 자동 백업 설정 파일
- `listening_history/`: 월별 원본 JSONL 기록
- `experience.json`: 추천·홈 구성 규칙

ZIP을 만들 필요가 없습니다. 내부 영구 저장도 함께 유지하며, 백업이 실패해도 내부 원본을 지우지 않습니다. 일반 정보의 이전 백업 파일은 보존합니다. 월별 청취 파일의 이전 사본이 최신 파일의 정확한 바이트 접두사일 때만 중복 사본을 정리합니다. 고유 청취 기록은 삭제하지 않습니다.

**백업 폴더에서 복원**은 누락된 정보 파일을 채우고 청취 기록을 ID별로 병합합니다. 기존 로컬 정보와 더 최근의 청취 체크포인트는 보존합니다. 다른 기기의 저장소 경로/MediaStore ID와 음원 쓰기 권한은 그대로 이식되지 않을 수 있습니다. 앱 설정·재생 목록 전체 복원에는 기존 백업/복원 화면에서 설정 JSON을 이용하세요.

## 온디바이스 청취 기록과 추천

재생 서비스에서 기록하므로 화면을 닫아도 수집합니다. 재생 중 10초마다 저장하고, 멈춤·탐색·전환·종료 때 추가 저장합니다. 강제 종료나 전원 손실 시 마지막 10초와 아직 저장하지 못한 이벤트는 유실될 수 있습니다. 저장 실패는 표시하고 재시도합니다.

원본에는 재생 발생 ID, 곡/아티스트/앨범/장르, 청취 시작·종료·실제 청취 시간, 탐색 위치, 속도, 반복/셔플 상태, 앱 음량, 즐겨찾기, 음원의 추가/수정 시점, 시간대와 알 수 있는 파일 정보가 포함됩니다. 출력 장치 목록은 **사용 가능한 장치 유형**이며 실제 선택 경로라고 단정하지 않습니다. 지원되지 않거나 알 수 없는 값은 비워 둡니다. 개인정보나 청취 이력을 서버로 업로드하지 않습니다.

90일 자동 삭제를 제거했습니다. 기존에 남아 있는 이력은 원본 파일을 보존하면서 가져옵니다. 이미 이전 앱이 삭제한 이력은 복원할 수 없습니다. 데이터베이스는 인덱스 검색용이며 JSONL 원본에서 다시 구축할 수 있습니다.

월을 선택하면 곡/아티스트/장르 선호, 시간대, 같은 청취 세션의 장르 전환, 재청취 간격 중앙값, 연속 반복, 완주와 빠른 건너뛰기를 분석합니다. 추가 후 첫 청취까지의 간격도 원본에서 계산할 수 있습니다. 중단 후 재개와 탐색은 같은 재생 발생으로 묶어 재생 횟수가 부풀지 않도록 합니다.

홈 추천은 누적 청취 선호, 장르, 재청취/새 곡, 즐겨찾기와 분석된 음향 유사도를 활용합니다. 최근 90일의 시간대별 장르 취향, 장르 전환, 빠른 건너뛰기, 재청취 간격과 음원 추가 시점도 반영합니다. 이 90일 범위는 최근 패턴 분석용이며 원본 기록을 삭제하는 정책이 아닙니다. 최근 재생 곡에 감점을 주고 같은 아티스트가 연속되는 것을 줄입니다. 규칙과 가중치는 오픈소스 코드와 JSON으로 확인할 수 있습니다. 상용 스트리밍 서비스의 대규모 모델과 동등한 품질을 주장하지 않습니다.

## 오디오 분석

충전 중·유휴 상태·저장소와 배터리 여유가 있을 때 실행합니다. 예약 버튼도 같은 조건을 사용합니다. 음악 파일을 곡 전체에 걸쳐 디코딩해 PCM SHA256, RMS/피크 음량, 영교차율, 주파수대 에너지, 256구간 파형을 저장합니다. PCM 해시는 동일하게 디코딩된 오디오의 지문입니다. 다른 믹스·리마스터·다른 디코더의 결과가 같은 해시라고 보장하지 않습니다. 주파수·에너지 유사도는 보조 신호이며 곡의 동일성이나 장르를 확정하는 모델이 아닙니다. 기기 디코더가 지원하지 않는 파일은 건너뛰고 실패 항목을 7일 동안 반복 분석하지 않습니다.

## APK 없는 데이터 갱신

`experience/default.json` 형식의 파일을 가져오면 앱 재설치 없이 추천 가중치와 지원되는 홈 섹션 순서를 바꿀 수 있습니다. 선택적으로 이 저장소의 규칙 파일을 Wi-Fi에서 매일 확인할 수 있습니다. 수동 규칙 가져오기는 자동 갱신을 끕니다. 호환되지 않는 규칙은 거절하고 기존 규칙을 유지합니다.

이 경로는 실행 코드·APK를 받지 않습니다. 새로운 네이티브 기능, 버그 수정이나 권한 추가에는 여전히 서명된 APK 업데이트가 필요합니다. Android/Play Protect 경고가 제거된다고 보장할 수는 없습니다. 기존 설치와의 호환성을 위해 패키지 ID와 서명 계보는 유지합니다.

기존 GPL 앱과 호환되는 Media3(Apache 2.0), SQLite, WorkManager를 활용하며 추가 DSP 구현도 GPL-3.0-or-later로 공개합니다.
