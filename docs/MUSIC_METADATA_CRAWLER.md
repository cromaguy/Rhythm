# 음악 정보 수집 및 사용자 지정 사이트

첨부한 `bugs-kotlin-crawler.zip`의 Kotlin/JVM 수집기를 `:crawler`로 통합했습니다. 앱의 최소 API 26, Java 17, Kotlin·OkHttp·코루틴 버전을 기존 프로젝트와 맞춥니다.

## 앱에서 사용

- 로컬 곡의 **정보 → 편집 → 음악 정보 가져오기**에서 벅스, 지니, 멜론을 선택하고 곡·앨범·아티스트를 검색합니다. 결과에는 서비스별 ID에 해당하는 상세 주소가 표시되며, 곡 검색에는 제공되는 경우 아티스트도 표시됩니다.
- 결과를 누르면 수집한 필드와 각각의 출처를 확인할 수 있습니다. 가져올 항목을 선택하고 **선택 항목 적용**을 누르면 편집 중인 값이 바뀝니다. 파일에 기록하려면 기존 편집 화면에서 **저장**을 눌러야 합니다. 누락·선택 해제된 필드는 기존 값을 유지합니다.
- 앨범 검색 결과의 제목은 곡 제목 대신 앨범 필드에 적용합니다. 아티스트 소개·데뷔일·프로필 이미지는 미리보기에서 확인할 수 있습니다. 로컬 파일의 곡 태그에 대응하지 않는 아티스트 프로필 필드는 기록하지 않습니다.
- 가사 편집기의 **음악 사이트에서 가사 찾기**에서 공개 가사를 가져올 수 있습니다. 선택한 가사는 편집기에 적용되며 자동 저장 설정에 따라 파일 저장 및 음원 내장을 시도합니다. 동기화되지 않은 가사이므로 원문 형식으로 열고 시간 오프셋을 초기화합니다.
- 이미지가 선택되면 앱 캐시에 JPEG로 준비한 뒤 기존 파일 메타데이터 저장 기능에 전달합니다. 이미지 요청이 실패하면 이미지를 선택 해제하고 다른 필드만 가져올 수 있습니다.

## 라이브러리 전체 정보 가져오기

**설정 → 미디어 스캔 → 라이브러리 정보 및 가사**에서 실행합니다. 온라인 연동이 켜져 있어야 하며, 재생하지 않은 로컬 음원도 처리합니다.

- 곡 태그, 아트워크, 아티스트·앨범 소개, 가사를 각각 선택할 수 있습니다. 기존 값, 수동 편집값, 기존 아트워크 및 로컬·내장 가사는 건너뜁니다. 같은 앨범과 아티스트를 중복 처리하지 않으며, 개별 곡 재생 시 사용하는 이미지·정보 인프라에도 같은 저장소를 연결했습니다.
- 제목과 아티스트가 일치하는 유일한 검색 결과만 자동 적용합니다. 같은 이름의 여러 버전이나 다른 아티스트의 커버는 자동 선택하지 않습니다. 식별 정보가 부족하면 기존 편집 화면에서 검색 결과를 직접 선택할 수 있습니다.
- 사이트마다 한 번에 한 요청만 보내고 요청 시작 사이에 최소 3초를 둡니다. 벅스 모바일·PC는 같은 제한을 공유합니다. 곡 사이에는 기존 API 폴백을 위한 2초 간격도 둡니다. 429 응답은 최소 15분 및 `Retry-After`, 401·403 또는 차단 페이지는 24시간 대기합니다. 서버 오류에는 지수 대기를 적용하고 사이트별 대기 시간은 앱 재시작 후에도 유지합니다. 차단을 회피하거나 재시도 폭주를 일으키지 않습니다. 찾지 못한 필드는 7일간 조회 결과를 재사용하며 새로운 미조회 필드는 별도로 조회할 수 있습니다.
- 기본적으로 요금 없는 네트워크에서 배터리·저장 공간이 충분할 때 실행합니다. 알림과 화면에서 진행률을 확인하고 일시 정지할 수 있습니다. 곡마다 진행 위치를 저장하며 프로세스 종료 또는 실행 구간 제한 후 WorkManager가 이어서 실행합니다. 새로 추가된 음원은 기존 실행 완료 후 다음 실행에 포함됩니다.
- 영구 저장을 켜면 메타데이터와 출처는 `filesDir/music_metadata/records`, 아트워크는 `images`, 가사는 `lyrics`에 저장합니다. 캐시 삭제·라이브러리 재검색 후에도 적용합니다. 앱 데이터 삭제·제거 후에도 보관하려면 **저장한 정보 및 가사 내보내기**로 사용자가 선택한 폴더에 ZIP을 저장하세요. 영구 저장을 끄면 새 메타데이터는 제한된 메모리 저장소만 이용하며, 이미 저장된 영구 기록은 유지합니다. 다시 켜면 남아 있는 메모리 기록도 영구 저장합니다.
- **채운 태그와 아트워크를 음원에 저장**은 기존 파일 태그 작성기를 사용합니다. Android 파일 쓰기 동의는 실제 쓰기와 동일한 볼륨 URI로 요청합니다. 거부하더라도 앱 정보·가사 파일 수집은 진행하고 음원 쓰기는 대기 목록에 남깁니다. **음원 파일에 저장** 버튼으로 권한을 허용한 뒤 다시 처리할 수 있습니다. 현재 곡의 파일 쓰기는 다른 곡으로 넘어갈 때까지 보류합니다. 파일 형식에서 내장을 지원하지 않는 경우에도 저장한 가사 파일은 유지됩니다.

## 가사 API 및 자동 저장

**설정 → API 관리 → 가사 API**에 **음악 사이트 (크롤링)** 소스를 추가했습니다. 기존 API 활성화 상태, 기본값, 저장된 우선순위 번호를 유지합니다. 새 API 소스는 명시적으로 켤 수 있으며 벅스·지니·멜론 중 선택한 제공자를 사용합니다.

일반 가사 조회 및 일괄 작업에서 기존 소스 순서(API/내장/로컬), 곡별 소스 설정, API 우선순위 및 폴백 처리를 이용합니다. 기존 API가 선택된 경우 크롤링은 폴백을 켰을 때 마지막 후보가 되며, 앞선 API의 일반 가사 백업도 유지합니다. 크롤링을 첫 API로 선택하면 폴백 설정에 따라 기존 API를 이어서 시도합니다. 일괄 작업은 이미 가사가 있는 음원을 먼저 제외하여 불필요한 네트워크 조회를 줄입니다.

**가사 파일 자동 저장**을 켜면 실제로 선택된 유효한 가사를 안정적인 음원 키로 저장합니다. 원본 `LyricsData` JSON, 일반 가사 TXT, 시간 정보가 있으면 LRC, 단어별 시간 정보가 있으면 별도 JSON을 유지합니다. 음원에 저장할 때는 동기화된 LRC를 우선합니다. 저장한 내용의 해시를 비교하여 반복 내장을 피하고 태그·가사 파일 쓰기를 음원별로 직렬화합니다. 기존 로컬·내장 가사를 내보내기용 파일로 복사할 때는 다시 음원에 내장하지 않습니다.

## 하이브리드 필터

미디어 스캔의 **하이브리드**는 화이트리스트가 포함 범위를 정하고 블랙리스트가 제외 항목을 정합니다. 두 목록에 동시에 속하면 제외하며, 화이트리스트가 비어 있으면 음원을 포함하지 않습니다. 같은 화면에서 편집할 목록을 전환할 수 있습니다. 목록 조회, 파일 스캔, 일괄 정보 수집 및 재생 대기열에 동일한 규칙을 적용합니다. `/Music` 폴더 규칙은 `/Music2`에 적용되지 않습니다.

## 사용자 지정 사이트

1. 검색창의 **사용자 지정 사이트**에서 유형을 선택하고 HTTPS 상세 페이지 주소를 엽니다.
2. 페이지의 제목·아티스트·가사·이미지 등의 요소를 눌러 필드 유형을 지정합니다.
3. 같은 사이트의 다른 항목 상세 페이지를 엽니다. 링크를 탐색하려면 **페이지 요소 선택**을 끕니다.
4. **검증**을 누르고 요소 선택을 켠 뒤, 첫 페이지에서 지정했던 모든 필드를 두 번째 페이지에서 다시 선택합니다.
5. **규칙 저장**은 두 페이지에서 동일한 선택 규칙이 각각 정확히 하나의 선택 요소에 일치할 때만 가능합니다.
6. 다른 상세 페이지에서 **추출**을 눌러 결과를 확인하고 **편집 화면에서 검토**를 선택합니다. 항목별 미리보기에서 적용 여부를 결정합니다.
7. **프로필**에서 저장한 규칙을 불러오거나 삭제합니다. 유형·사이트별 프로필이 분리되고 다른 출처에서는 사용할 수 없습니다.

저장되는 프로필은 선택 규칙·유형·검증 주소이며, 선택한 샘플 본문과 페이지 HTML을 포함하지 않습니다. 가져올 결과는 크기를 제한한 임시 캐시 파일로 전달하고 읽은 뒤 삭제하므로 가사 전문을 Activity Intent에 담지 않습니다. 완료하지 않은 학습은 화면 재생성 시 초기화되며, 저장한 프로필은 유지됩니다.

## 보완 사항

- Android에서 사용할 수 있는 `URLEncoder.encode(String, String)`으로 변경했습니다.
- 네트워크 요청은 메인 스레드 밖에서 실행하며, 코루틴 취소는 응답 본문 수신 중에도 OkHttp 요청을 취소합니다. 응답 크기를 헤더뿐 아니라 chunked 전송에도 제한합니다.
- 지니의 JavaScript 상세 링크와 멜론의 `onclick` 상세 링크에서 서비스별·유형별 ID를 추출합니다. 벅스의 `곡정보` 링크 대신 검색 행의 실제 곡명을 표시합니다.
- 서로 다른 서비스의 숫자 ID를 공유하지 않습니다. 벅스 모바일·PC는 같은 벅스 카탈로그의 보완 소스로만 함께 사용합니다.
- 가사 줄바꿈을 보존하고, 발매 연도는 연월일 숫자를 합치는 방식 대신 날짜에 포함된 연도에서 추출합니다.
- 선택기에서 생성하는 부모/자식 CSS 규칙을 허용했습니다. 검증 페이지 변경 및 실패한 재선택은 기존 검증 결과를 무효화합니다.
- WebView는 HTTPS 탐색, 혼합 콘텐츠 차단, 파일·콘텐츠 접근 차단을 적용하고, 메인 프레임 메시지만 받습니다. 입력·편집 요소를 추출하지 않습니다.
- JSON은 명시적 키로 인코딩해 release 난독화에서도 같은 형식을 사용합니다.

## 검증

```bash
./gradlew :crawler:test :app:testGithubDebugUnitTest :app:assembleGithubDebug
./gradlew :app:assembleGithubRelease :app:lintGithubDebug
# 공개 음악 페이지를 호출하는 명시적인 스모크 검사 (가사 전문을 출력하지 않음)
./gradlew :crawler:smoke
```

일반 단위 테스트는 실제 음악 서비스에 접속하지 않습니다. 파서 테스트는 고정 HTML을, 응답 크기 및 취소 테스트는 로컬 HTTP 서버를 사용합니다. GitHub Android CI에 크롤러와 앱 단위 테스트를 추가했습니다.

사이트 개편이나 접근 제한에 따라 일부 필드가 없을 수 있습니다. 새 템플릿은 별도 프로필로 다시 학습해야 합니다. 공개 페이지 접근은 가사·이미지의 재배포 권한을 의미하지 않으며, 로그인·CAPTCHA·재생 보호를 우회하지 않습니다.
