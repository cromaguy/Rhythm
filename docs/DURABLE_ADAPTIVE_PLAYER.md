# 영구 보관과 가벼운 개인화

## 이미지와 영상

- YouTube 링크는 [NewPipeExtractor v0.26.5](https://github.com/TeamNewPipe/NewPipeExtractor/tree/v0.26.5)의 Android 호환 Java 추출기를 사용합니다. GPL-3.0-or-later이며 Python이나 외부 실행 파일을 설치하지 않습니다.
- Android에서 쓰지 않는 Rhino JSR-223 데스크톱 어댑터는 의존성에서 제외하고, NewPipe의 Android용 R8 규칙을 따릅니다. 실제 추출기는 해석 모드를 명시하므로 데스크톱 JVM 동적 링크나 JavaBean 변환을 사용하지 않습니다.
- 영상 전용 스트림을 최대 720p·30fps로 선택합니다. 같은 해상도에서는 WebM을 우선하고, 예상 48MB 안의 후보를 우선합니다. 실제 다운로드는 파일당 96MB에서 중단됩니다. 기기에서 지원하는 WebM/MP4를 재인코딩 없이 보관하므로 열·배터리 사용과 중복 오디오를 줄입니다.
- 기본 다운로드는 Wi-Fi 등 비과금 연결에서 진행합니다. 관리 화면에서 모바일 데이터 사용을 명시적으로 선택할 수 있습니다. 제한·삭제·비공개 영상의 접근 제한을 우회하지 않습니다. 저장 후에는 기존 커버 영역에 잘라 맞추며, 영상은 무음이고 원래 음악 재생을 유지합니다.
- 앱 내부 원본 이미지는 앱 전용 저장소에 그대로 보존됩니다. 외부 백업에는 원래 바이트·길이·SHA-256을 담은 `.t2art` 파일을 사용합니다. 이미지 확장자·MIME·헤더를 노출하지 않으므로 갤러리 이미지로 인식되지 않습니다. **암호화 형식은 아니며** 복원 시 원본을 바이트 단위로 돌려줍니다. 기기 암호화 키에 종속시키지 않아 재설치 후에도 복구할 수 있습니다.
- 기존 백업의 이미지는 백그라운드에서 변환합니다. 새 파일을 다시 읽어 일치함을 검증한 뒤에만 기존 외부 사본을 제거합니다. 앱 내부 원본은 제거하지 않습니다. `.nomedia`도 T2Rhythm의 메타데이터 하위 폴더에만 생성합니다. 폴더 권한이 없으면 원본을 건드리지 않고 설정에서 폴더를 다시 선택하도록 합니다.
- 커버 이미지는 현재 화면을 우선합니다. 플레이어의 이전·다음 곡, 라이브러리 화면 바로 바깥 최대 네 항목만 미리 읽습니다. 스크롤 중에는 이전 요청을 취소하며 추측 디코딩은 동시에 하나만 실행합니다. 먼 항목은 기존 Lazy 목록·그리드가 필요할 때 구성합니다. 내장 커버의 인코딩 캐시(32MB), 디코딩 메모리 캐시(최대 24MB)도 제한합니다.

## 충전 중 분석

청취 원본 기록은 계속 저장하지만, 음향 분석·모델 훈련·상세 패턴 계산은 충전·유휴·저장 공간 조건을 갖춘 WorkManager에서 실행합니다. 단일 낮은 우선순위 분석 스레드가 약 16ms 작업 뒤 144ms 쉬며, 충전 해제·발열·취소를 확인합니다. 이어서 처리할 수 있는 학습·색인은 90초 단위로 체크포인트를 저장합니다. PCM 분석은 파일 전체를 읽되 충전이 해제되면 다음 실행으로 미룹니다.

화면을 열거나 피드백 버튼을 누를 때 전체 청취 저널을 재분석하지 않습니다. SQLite 누적 요약과 저장된 모델을 읽습니다. 후보는 최대 2,000곡, 음향 비교는 상위 128곡으로 제한하고 탐색 후보를 순환시킵니다. 원본 이력은 이 제한과 관계없이 계속 보관합니다. 월별 상세 예시는 최근 청취 구간·동작을 각각 최대 5,000건 사용하며, 전체 기록과 누적 취향 색인은 별도로 유지합니다.

최근 90일의 장르 선호에는 30일 감쇠를 적용하고, 재청취 간격은 중복되지 않는 재생 시작 시점으로 누적 요약합니다.

추천에는 실제 매 재생의 청취 비율, 시간·요일·장르 전환, 위치·출력 기기·날씨·밝기·볼륨·선택적 주변 소음, 이동·낮밤 맥락이 들어갑니다. 이동은 5Hz 가속도 요약과 신선하고 정확한 위치 속도로 보수적으로 추정합니다. 자동차와 기차 등 구별하기 어려운 신호는 합쳐 표시하며, 모호한 경우 미확인으로 남깁니다. 현재 활동을 직접 지정할 수도 있습니다. 낮밤은 날씨의 주야 정보, 오프라인 태양 고도, 위치가 없으면 현지 시각 추정 순으로 판단합니다. 원시 센서 파형은 저장하지 않습니다.

## 믹스 서랍과 좋아요

새 추천마다 고유 세대와 정확한 곡 순서를 영구 파일로 보관합니다. 평가 키도 세대별로 다르므로 이전 목록의 좋아요·싫어요가 새 목록의 버튼 상태에 붙지 않습니다. 서랍에서 지난 목록을 열고, 재생하거나 기존 일반 플레이리스트로 저장할 수 있습니다. 평가 취소·반대 평가 모두 가능합니다.

곡·앨범·아티스트 좋아요는 독립적입니다. 곡은 기존 즐겨찾기·재생목록·서비스·위젯 갱신 경로를 유지합니다. 중앙 더블 탭은 좋아요 설정만 수행하며 반복해서 눌러도 취소하지 않습니다. 일반 버튼으로는 취소할 수 있습니다. 양쪽 더블 탭 이동은 기본 10초이고 제스처 설정에서 5~60초로 조절합니다.

‘취향 재확인’은 기본 켜짐이며 설정에서 끌 수 있습니다. 원래 좋아요·알 수 있는 최초 시점·반복 확인 이력을 보존하고, 7~21일 범위의 균등한 순환 간격으로 다시 확인합니다. 사용자가 직접 상세 화면을 열거나 커버를 조작해야 노출을 기록합니다. 자동 곡 전환·보통 화면 렌더링은 노출이 아닙니다. 미응답·미확인을 싫어요로 간주하지 않습니다. 다시 누르면 현재의 긍정 신호를 갱신합니다. 재확인 안내에서 실제 좋아요 취소도 할 수 있습니다. 기존 좋아요의 과거 최초 시점을 알 수 없으면 시간을 만들어내지 않습니다.

## 업데이트 범위

호환되는 추천 가중치·홈 구성 JSON은 고정된 저장소의 HTTPS 경로에서 크기·스키마·값·최소 앱 버전을 검사한 뒤 적용합니다. 기존 정상 설정도 보관합니다. 업데이트 설정 화면에서 즉시 확인하거나 자동 Wi-Fi 갱신을 켤 수 있습니다. 새 네이티브 UI, 권한, 라이브러리 변경은 서명을 검증한 APK 설치가 필요합니다. GitHub의 임의 Kotlin/Dex 실행 코드를 내려받아 바꾸는 기능은 제공하지 않습니다.
